# STM32 井下环境监测节点 —— 数据上报协议文档（v2.1）

> 本文档面向 STM32 固件开发者，定义单片机与微信小程序之间
> 的两种数据上报通道（BLE 蓝牙透传 / MQTT 发布）的统一数据协议。

---

## 1. 总体框架

```
┌──────────────┐   BLE UART 透传(FFE0/FFE1)   ┌──────────────┐
│              │ ───────────────────────────► │              │
│   STM32      │                              │  微信小程序    │
│  采集节点     │   MQTT publish (JSON)        │              │
│              │ ───────────────────────────► └──────────────┘
└──────────────┘        （经 MQTT Broker 中转）
```

- STM32 每 1~5 秒上报一帧环境数据（建议 2 秒）；
- **两种通道的数据帧格式完全一致**（JSON 文本），固件只需实现一套组包逻辑，
  由不同通道发送；
- 小程序同一时间只启用一种通道（BLE 与 MQTT 互斥）。

---

## 2. 数据帧定义（JSON）

### 2.1 标准数据帧

v2.1（当前固件，所有字段向后兼容，旧字段缺省时小程序按默认处理）：

```json
{"temp":25.0,"humi":60.0,"gas":110,"status":0,"fan":0,"alarm":0,"helmet":2,"head":1}
```

### 2.2 字段说明

| 字段 | 类型 | 单位 | 取值范围 | 含义 | 版本 |
|---|---|---|---|---|---|
| `temp` | number | ℃ | -50.0 ~ 150.0 | 井下环境温度，保留 1 位小数 | v1 |
| `humi` | number | %RH | 0.0 ~ 100.0 | 井下环境相对湿度，保留 1 位小数 | v1 |
| `gas`  | number | ppm | ≥ 0 | 有害气体浓度（CH₄/CO/H₂S 等传感器读数），取整 | v1 |
| `status` | number | - | 0 或 1 | 井下安全状态：**0-正常，1-危险告警**（任一告警即置 1） | v1 |
| `fan`  | number | - | 0 或 1 | 散热风扇状态：0-关闭，1-运行 | v2 |
| `alarm` | number | - | 0 ~ 7 | 告警位掩码：bit0 温度过高 / bit1 气体超标 / bit2 震动告警，可同时置位 | v2 |
| `helmet` | number | 人 | 0 ~ 99 | K230 安全帽检测：**戴**安全帽人数（K230→UART4→STM32 转发） | v2.1 |
| `head` | number | 人 | 0 ~ 99 | K230 安全帽检测：**未戴**安全帽人数 | v2.1 |

> `helmet`/`head` 为可选字段：固件未接 K230 时不发送（或旧固件），小程序自动隐藏
> 安全帽检测卡片；K230 掉线后 STM32 冻结最后一帧数值继续上报。

### 2.3 字段约束（固件侧务必遵守）

1. **严格 JSON 语法**：双引号、无多余逗号、无注释；键名全小写、不得改名；
2. `status` 只允许 `0` 或 `1`，禁止发送其他值（如 2、-1）；
3. 传感器故障时**不要发送** NaN / null / 负温度溢出等非法值——
   建议发送上一帧缓存值并置 `status=1`（危险告警），由地面端人工介入；
   （小程序解析层对非法字段会整帧丢弃，无法触发告警）；
4. 一帧总长度建议控制在 **100 字节以内**（BLE 单包 20 字节分包后仍可恢复，
   但更短更稳）。

## 3. 通道一：BLE 蓝牙透传协议

### 3.1 服务与特征约定（BLE UART 透传）

| 项目 | UUID | 说明 |
|---|---|---|
| 透传服务 | `0000FFE0-0000-1000-8000-00805F9B34FB`（简写 FFE0） | JDY-31 / HC-08 等模块默认 |
| 数据上报特征（Notify） | `0000FFE1-0000-1000-8000-00805F9B34FB`（简写 FFE1） | 模块固件默认 notify 特征 |

> 使用其他模块（如 Nordic NUS）时，请同步修改小程序
> `utils/bleService.js` 顶部的 `SERVICE_UUID / CHAR_UUID` 常量。

### 3.2 帧格式

- 内容：标准 JSON 帧的 **UTF-8 文本**；
- 每帧结尾建议追加换行符 `\n`（`0x0A`）作为帧分隔（可选，小程序
  解析层以 `{...}` 括号匹配自动组帧，换行符仅用于加快边界识别与调试）；
- BLE 单包（MTU）通常为 20 字节，**允许一帧 JSON 被拆成多个 BLE 包**：
  小程序接收端维护半包缓冲区，自动拼接，固件无需关心分包；
- 连续两帧之间无需延时等待（支持粘包）。

### 3.3 STM32 参考实现（HAL + 伪代码）

```c
/* 传感器数据结构 */
typedef struct {
    float   temp;     /* 温度 ℃    */
    float   humi;     /* 湿度 %RH  */
    int32_t gas;      /* 气体 ppm  */
    uint8_t status;   /* 0正常 1危险 */
} mine_data_t;

/* 组包并发送（BLE UART 透传：往串口写即透传给手机） */
void Mine_SendFrame(mine_data_t *d)
{
    char buf[96];
    int len = snprintf(buf, sizeof(buf),
        "{\"temp\":%.1f,\"humi\":%.1f,\"gas\":%d,\"status\":%d}\n",
        d->temp, d->humi, (int)d->gas, d->status);
    /* 经蓝牙模块串口透传发送（HAL_UART_Transmit / printf 重定向均可） */
    HAL_UART_Transmit(&huart1, (uint8_t*)buf, len, 100);
}
```

> 发送间隔建议 2 秒：`osDelay(2000)` / `HAL_Delay(2000)`（RTOS / 裸机）。

### 3.4 下行指令（小程序 → 设备，阈值同步）

BLE 通道为双向透传，小程序可向 FFE1 特征**写** JSON 指令，
固件用串口接收中断 + 空闲断帧（`\n` 或线路空闲即为一帧）解析：

**指令帧（小程序 → 设备）：**

```json
{"cmd":"gas_max","val":80}\n
```

| 字段 | 说明 |
|---|---|
| `cmd` | 指令名，当前支持 `gas_max`（修改气体告警阈值，单位 ppm） |
| `val` | 参数值，`gas_max` 合法范围 1 ~ 9999 |

**应答帧（设备 → 小程序）：**

```json
{"cmd":"gas_max","ack":80}\n
```

- `ack` 为数值 = 修改成功后的阈值（设备侧报警线立即生效）；
- `ack` 为 `err` = 参数超范围，设备保持原阈值；
- 固件实现参考 `kuan/User/main.c` 的 `BLE_HandleCommand()`；
- 注意：**阈值不落 flash，设备重启后恢复固件默认值 50ppm**；
  MQTT 通道的下行主题 `mine/env/down` 为预留，本期未实现。

## 4. 通道二：MQTT 发布协议

### 4.1 连接参数

| 项目 | 约定 |
|---|---|
| 传输层 | MQTT over **WebSocket**（小程序 wx.connectSocket 限制） |
| URL | `ws://<服务器>:<端口>/mqtt`（小程序内写 `wxs://` 前缀自动适配） |
| 常用端口 | EMQX：8083(ws) / 8084(wss)；自建 Broker 需开启 websockets 监听 |
| ClientID | 建议 `mine-node-<设备编号>`（保证唯一） |
| KeepAlive | 60 秒（Broker 侧） |
| QoS | QoS 0（数据频率高，允许偶发丢包） |

### 4.2 主题（Topic）规划

| 主题 | 方向 | 说明 |
|---|---|---|
| `mine/env/up` | STM32 → Broker → 小程序（订阅） | **环境数据上报主题**（小程序连接页填写此主题） |
| `mine/env/down`（预留） | 小程序 → Broker → STM32 | 预留下行控制主题（阈值下发等，本期未使用） |

> 多节点部署时可按点位扩展：`mine/env/up/<节点编号>`，
> 小程序连接页填写对应主题即可。

### 4.3 消息体

- Payload：标准 JSON 帧（同第 2 章），UTF-8 文本，**无需**换行符；
- 保留消息（retained）建议关闭，避免小程序连上后先收到陈旧数据。

### 4.4 STM32 参考实现（esp-idf / AT 模块均可）

使用 AT 指令蓝牙/WiFi 模块（如 ESP8266 AT 固件）示例：

```c
/* 1. 连接 MQTT Broker（AT 指令，示例为 ESP-AT） */
/* AT+MQTTUSERCFG=0,4,"mine-node-01","user","pass",0,0,""   (4=MQTT over WS) */
/* AT+MQTTCONN=0,"broker.emqx.io",8083,0                     */
/* AT+MQTTSUB=0,"mine/env/up",0                              */
/* 2. 按周期发布数据帧 */
char payload[96];
int len = snprintf(payload, sizeof(payload),
    "{\"temp\":%.1f,\"humi\":%.1f,\"gas\":%d,\"status\":%d}",
    d->temp, d->humi, (int)d->gas, d->status);
/* AT+MQTTPUB=0,"mine/env/up","<payload>",1,0   (payload 需转义) */
```

## 5. 异常与容错约定（端到端）

| 场景 | STM32 侧行为 | 小程序侧行为 |
|---|---|---|
| 传感器读数异常 | 发送上帧缓存值并置 status=1 | 收到后正常弹窗告警 |
| JSON 组包失败 | 丢弃本帧不发送 | ——（收不到即不更新） |
| 半包/粘包/脏数据 | —— | 解析层自动拼接；非法帧整条丢弃，不影响连接 |
| BLE 断开 | 模块自动重广播 | 自动 toast 提示，可手动重连 |
| MQTT 掉线 | 模块/固件自行重连 Broker | 自动重连（3 秒间隔）+ 30 秒心跳兜底检测 |
| 气体超标(gas>阈值) | 可置 status=1（可选，地面阈值也可触发） | 长震动 + 弹窗告警（10 秒节流） |
