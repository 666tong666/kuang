## 2.5 串口输出人数（TTL 转 USB）

`helmet_inference.py` 已内置串口输出，每帧发一行（115200, 8N1）：

```
helmet:2,head:1\r\n     ← 戴帽人数 / 未戴帽人数
```

### 接线（3 根线，断电接）

| TTL 转 USB 模块 | K230 板 |
|---|---|
| RX | 板子 UART TX（TXD） |
| TX | 板子 UART RX（只发不收可不接） |
| GND | GND（**必须共地**） |
| VCC/5V | **不接** |

- 模块若有 5V/3.3V 跳线，选 **3.3V**；官方文档警告禁用劣质 CH340G 黄跳帽模块（可能烧 IO）
- 亚博板有专用串口排座的话直接用配套 PH2.0 线；脚本会**自动优先用亚博固件的
  `ybUtils.YbUart`**（自动处理引脚映射），找不到该库才回退 FPIOA 映射
  UART1（默认 pin11=TX / pin12=RX，可在脚本顶部 `UART_TX_PIN/UART_RX_PIN` 改）
- 引脚位置不确定时：跑一下脚本看启动日志 `[uart] ...` 用了哪种方式；或跑亚博官方
  「串口通信」基础例程看它用的引脚，把 `UART_TX_PIN/UART_RX_PIN` 改成一样的

### PC 端看数据（两种方式任选）

1. **串口助手**（SSCOM/XCOM 等）：选 TTL 模块的 COM 口，115200-8-N-1，ASCII 显示
2. **本项目脚本**（会实时打印每行人数）：
   ```bash
   D:/230/venv2/Scripts/python.exe uart_reader.py --list   # 插上模块后找新 COM 口
   D:/230/venv2/Scripts/python.exe uart_reader.py COM7     # 115200 默认
   ```

### 可调参数（脚本顶部配置区）

| 参数 | 默认 | 说明 |
|---|---|---|
| `UART_ENABLE` | `True` | 关掉串口输出 |
| `UART_BAUDRATE` | `115200` | 与 PC 端一致 |
| `UART_SEND_EVERY_FRAME` | `True` | `False`=人数变化时才发（串口更安静） |

## 3. 板端脚本说明（helmet_inference.py）

与嘉楠官方 yolov8n 检测示例完全同构（V1.4.x media API）：

- sensor 双通道：chn0 YUV420 绑显示层（AI 慢不卡预览），chn1 RGB888P(=NCHW) 给 AI
- ai2d 做 letterbox（等比缩放 + 右/下 pad 128）→ 640×640 NCHW uint8
- kmodel 内已烧入归一化（uint8→0~1），板端无需再算
- 后处理：阈值过滤 → **分类别 NMS**（helmet/head 互不抑制）→ 画框
- 输出 `[1,6,8400]`：4 框参数 + helmet/head 两类 sigmoid 分数

可调参数（脚本顶部配置区）：

| 参数 | 当前值 | 说明 |
|---|---|---|
| `DISPLAY_MODE` | `"virt"` | IDE 预览 / `"lcd"` / `"hdmi"` |
| `CONF_THRESH` | 0.30 | 怕漏检降到 0.25 |
| `NMS_THRESH` | 0.45 | YOLO 标配 |
| `LABELS` | `("helmet","head")` | **必须与训练 data.yaml 一致，勿改顺序** |

## 6. 关键参数 / 经验值

| 参数 | 训练 | K230 部署 | 说明 |
|---|---|---|---|
| input shape | 640×640 | 640×640 | 静态输入，KPU 效率高 |
| input layout | NCHW float32 | **NCHW uint8**（preprocess=True） | 归一化烧进 kmodel |
| conf threshold | val 0.001 | **0.30**（可 0.25） | 安全帽宁可误报不能漏报 |
| NMS IoU | – | 0.45 | 分类别 NMS |
| labels | helmet=0, head=1 | 严格一致 | 反了"安全/危险"判断就反了 |

## 7. nncase 工具链踩坑记录（PC 侧）

| 坑 | 修复 |
|---|---|
| PyPI 的 nncase 不带 KPU 后端（`check_target('k230')=False`） | 用 kendryte 官方 wheel：`tools/nncase-2.10.0-*.whl` + `tools/nncase_kpu-2.10.0-*.whl`（手动解压覆盖到 site-packages） |
| nncase 硬绑 .NET 7，系统只有 .NET 8+ | 运行前设 `DOTNET_ROLL_FORWARD=Major` |
| venv3 的 cv2/numpy 被装坏 | 校准图用 PIL；numpy 重装 |
| GitHub release 直连超时 | 用嘉楠国内 CDN：`https://download.kendryte.com/developer/tools/nncase/v2.10.0/`（curl 会被沙盒截断，用 PowerShell Invoke-WebRequest） |
| nncase Simulator 报 DLL 找不到 | 把 site-packages 根目录加进 `PATH` + 设 `NNCASE_PLUGIN_PATH` |
| 预处理除两次 255（分数全死 ~0.0007） | `input_range=[0,1]` 时 `std` 必须 `[1,1,1]` |
| 校准张量缺 batch 维 | 每个样本包成 `[array]`，shape `[1,3,640,640]` |

## 8. 故障排查（板端）

| 现象 | 原因 / 处理 |
|---|---|
| `找不到 kmodel` | kmodel 不在 `/sdcard/`；确认 U 盘拷贝完成（3.5MB） |
| `kpu.load_kmodel` 报版本/格式错误 | kmodel(2.10 编译) 与固件 nncase 运行时不匹配 → 报我，用 2.9 重编一版 |
| `No available sensor` | 摄像头没插好或不在默认 CSI 口；脚本会自动试 `Sensor(id=2)`，还不行检查排线 |
| `ImportError: media.sensor` | 固件过老，需 CanMV V1.4.x media API（你的 V1.4.3 没问题） |
| 画面黑 / 无预览 | `DISPLAY_MODE` 不对；无屏用 `"virt"` |
| 画面上下颠倒 | 取消脚本里 `sensor.set_hmirror / set_vflip` 注释 |
| FPS 很低（<3） | 正常范围：640×640 uint8 在 K230 约 5~10 FPS；要更快用 320×320 重训 |
| 检测框位置飘 | 摄像头分辨率与 AI_W/AI_H 不符；或 `ratio` 相关参数被改动 |
| 长时间运行内存溢出 | 脚本已每帧 `gc.collect()`；仍出现则重启板子 |
